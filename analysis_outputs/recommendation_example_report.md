# 온살핌 개인별 생활 패턴 기반 알림 기준 추천 사례

작성일: 2026-10-14. AIHub 로컬 원본과 기존 EDA만 사용했다. 기존 EDA 파일은 수정·삭제하지 않았으며 개인정보와 원본 데이터는 외부로 전송하지 않았다. 모델 학습·운영 알림 확정은 하지 않았다.

## 실제 계산 결과

[추천 결과 예시 — AIHub 실제 독거노인 가구 E001]

- 분석 기간: 2023-05-01 ~ 2023-05-28 (기준선 2023-05-01~2023-05-14, 검증 2023-05-15~2023-05-28)
- 평소 첫 활동: 01:01 ± 62분 (00:00 이후 첫 **관측** 활동의 산술평균 ± 표본표준편차, ddof=1)
- 14일 중 활동 확인 가능 일수: 14일 (기준선)
- 개인별 추천 기준: 03:09까지 활동 신호 미확인 시 '생활 확인' **알림 후보**
- 이후 14일 적용 결과: 알림 후보 1일 / 정상 13일 / 검증 불가 0일
- 데이터 관측률: 99.98% (28일, 4031/4032 슬롯)
- 추천 근거: 기준선 14일 모두 활동 대리 지표가 관측되었고, 첫 관측 활동 시각의 90분위수 02:39에 30분을 더해 03:09을 얻었다. 다만 첫 관측이 새벽에 집중되어 이 기준은 기상 지연을 설명하지 못한다. 이후 14일의 후보 1일은 위험 사건의 정답이 아니라 생활 확인을 검토할 날짜다.


**내부 해석: 90분위수 + 30분은 사용자가 지정한 실험용 설계값이며 검증된 응급 기준이 아니다.** 이 가구의 첫 움직임은 새벽에 집중되어 계산된 기준을 아침 생활 확인 또는 기상 시각 기준으로 채택하기 어렵다. 보기 좋은 사례를 만들기 위해 가구·기간·하루 시작 시각을 바꾸지 않았다.

## 대상 선정과 원본 대조

- 기존 `analysis_outputs/analyze_dataset.py`, `daily_coverage.csv`, `household_coverage.csv`의 경로·집단별 키 정렬·필드를 재사용했다. 기존 추천 스크립트는 없어서 `analysis_outputs/aihub_example_recommendation.py`를 새로 작성했다. EDA 스크립트를 import하면 전수 집계를 다시 쓰므로 import하지 않고 스트리밍 JSON 함수만 AST로 추출해 사용했다.
- 확보된 전체 927가구의 EDA 일별 관측률에서 가명 ID 오름차순으로 검색했다. 연속28일 각각 130/144슬롯 이상(90.28%)인 적격 가구는 891가구이고 첫 가구는 **E001**다. E001은 조건을 충족하여 대체하지 않았다. 이 가구의 **시간 순서상 최초** 적격 28일을 선택했다. 대상·기간 선택에는 알림 결과나 패턴 모양을 사용하지 않았다.
- EDA와 같은 가명화: B 키 정렬 순번은 E001…, A 키 정렬 순번은 N001…. 원본 ID·성별이 들어간 member 이름은 결과에 노출하지 않는다. 원본 위치는 로컬 `Dataset` 디렉터리이며 선택 압축묶음은 `Dataset\68.독거노인 돌봄용 위험감지 데이터\3.개방데이터\1.데이터\Validation\01.원천데이터\VS_B.기존수집_01.환경측정.zip`다. CRC32와 내부 파일 크기를 JSON에 남겼다.
- 선택 가구 환경 CSV 70,348행을 50,000행 청크로 읽어 대상28일만 유지했다. 분석 센서는 `Activity_IR`, `Temperature`, `Humidity`, 시간은 `Time`이다. 기존 EDA의 유효 관측 정의(수치·유한값, Activity_IR≥0, 온도 -40~85, 습도0~100, 10분 격자)로 원본 일별 수를 다시 계산해 28일 모두 EDA와 일치함을 확인했다. 온도 범위는 기존 EDA의 검토 가정이며 기기 정격을 뜻하지 않는다.

## 날짜·결측과 첫 활동 통계

- 모든 시각은 **원본의 timezone 없는 시각**이다. KST 여부는 확정되지 않았다. 하루는 00:00 이상 다음날00:00 미만이며 예상 기록은 00:00~23:50의 144개 10분 슬롯이다. 기록시각이 센서집계의 시작/끝 중 무엇인지도 명세가 없어 확정하지 않는다.
- 활동 대리 지표는 유효한 `Activity_IR > 0`이다. PIR ON/OFF·재실·기상·건강 정상과 동일하지 않다. 첫 활동은 각 달력일에서 이 조건을 처음 만족하는 **관측** 시각이다. 0은 기록된 무움직임 대리값, NaN은 관측 누락으로 분리했고 보간·0채움을 하지 않았다.
- 28일 전체 유효 관측률 99.975198% (4031/4032), 기준선 99.950397% (2015/2016), 검증 100.000000% (2016/2016), 최소 일별 관측률 99.305556%다. 누락 슬롯은 `[{'start': '2023-05-01 00:00:00', 'end': '2023-05-01 00:00:00', 'missing_slots': 1}]`이며, 2023-05-01 00:00은 가구 첫 기록00:10 이전의 **창 경계 미관측**이다. 장비 장애로 확정하지 않는다. 다른 27일은 완전 관측이다.
- 최초14일 활동 확인 가능 14/14일. 첫 관측까지의 시간창에도 동일 품질검사를 적용해 확인했지만 5월1일의 미관측00:00에 실제 활동이 있었는지는 알 수 없다. 따라서 실제 첫 활동 시각으로 단정하지 않는다.
- 평균은 자정 이후 분 단위의 산술평균 **61.4285714286분**(표시 01:01), 표본표준편차 **62.1235918097분**(표시 ±62분, ddof=1)이다. 원본은10분 해상도이며 평균의 초 단위는 통계 계산값일 뿐 측정 정밀도를 뜻하지 않는다. 범위 00:00~03:10, 중앙값 00:40이다. ‘평소’는 단14일의 요약이며 안정된 생활습관 확정이 아니다.

## 90분위수와 여유시간

정렬된 첫 관측 시각(자정 이후 분): `[0.0, 0.0, 20.0, 20.0, 20.0, 30.0, 40.0, 40.0, 50.0, 50.0, 110.0, 110.0, 180.0, 190.0]`.

선형 보간법(NumPy `method='linear'`): n=14, q=0.9, 0기반 순위 h=(n−1)×q=11.7. 양끝 값은 정렬 배열[11]=110분, [12]=180분이다. 따라서 p90=110 + 0.7×(180−110) = **159.0000000000분 = 02:39**. 여유30분을 더하면 **189분 = 03:09**다. 산식은 기준선14일에서만 계산했으며 검증14일로 다시 맞추지 않았다.

03:09는 10분 관측 격자에 맞춰 올림하지 않은 산식 결과다. 평가에 포함되는 마지막 예상 기록은03:00이고03:10은 제외한다. 03:09까지의 정확한 센서 이벤트 시간을 복원한 것은 아니다. 실제 운영 시의 격자 반올림·전송 지연 정책은 후속 설계가 필요하다.

## 이후14일 검증 및 고정기준 비교

기준선 2023-05-01~2023-05-14, 검증 2023-05-15~2023-05-28로 날짜가 겹치지 않는다(0일). ‘학습용’은 기준선 산정이라는 의미이며 모델을 학습하지 않았다.

평가 창은 각 날짜00:00~추천시각 **포함**이다. 예상 10분 슬롯에 유효 Activity_IR가90% 이상, 최대 연속 누락20분 이하, 마지막 예상 슬롯이 관측되어야 평가한다. 하나라도 미충족이면 **검증 불가**로 먼저 분리한다. 충분히 관측된 창에서 >0이 확인되면 ‘정상’(활동 확인), 모두0이면 ‘생활 확인 알림 후보’다. ‘정상’은 실제 건강이나 안전을 보증하지 않는다. 90% 허용 창에는 미관측 슬롯의 활동 가능성이 남으므로 후보도 위험 확정이 아니다. 이번 검증14일은 모든 평가 창이 완전 관측이므로 이 관측 부족 모호성은 없다.

## 제안서용 4줄 요약

AIHub 실제 가구 E001의 2023-05-01~2023-05-28 28일 데이터(관측률 99.98%)를 분석했다.
최초 14일 첫 관측 활동은 평균 01:01 ± 62분(표본표준편차)이며, 90분위수 02:39 + 30분으로 생활 확인 후보 기준 03:09을 계산했다.
겹치지 않는 이후 14일 적용 결과는 알림 후보 1일·활동 확인 13일·검증 불가 0일이며, 공통 09:00 기준도 후보 1일이었다.
첫 활동은 기상 시각이 아닌 새벽 움직임 대리 지표이며 원본 시간대도 미확정이므로, 본 사례는 실험 산식의 계산 예시이고 운영 응급 기준이나 위험 탐지 정확도를 검증한 결과가 아니다.
