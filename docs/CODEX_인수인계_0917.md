### 9/18 저녁 — 규칙 겹침 처리 + 단계 경보 (사용자 결정)

- **같은 세대·같은 위험도의 무활동 규칙이 겹치면**: 저장은 하되 승인 대기에서 '겹침' 표시. 복지사가 **[기존 규칙 대체]** 또는 **[거부]**. 대체하면 기존 규칙은 지우지 않고 끄고 `superseded_by/at/who` 기록. 기존 규칙의 **일부 세대만** 겹치면 대체 불가(나머지 세대 기준이 사라지므로) → 예외 문장으로 안내.
- 겹침은 **승인 시점에 다시 계산**(`engine.approve_rule`) — 저장 뒤 상황이 바뀌었을 수 있다. 꺼진 규칙을 **다시 켤 때도** 검사(`engine.toggle_rule`, 409).
- **위험도가 다르면 단계 경보**(예: 3시간 주의 → 8시간 긴급). `care_monitor.judge(..., idle_levels=)` 가 넘은 단계 중 가장 높은 위험도. 무활동 주의가 배터리 주의보다 먼저. 무활동 규칙의 위험도는 주의·긴급만(`scope.IDLE_SEVERITIES`). 주의 기준 ≥ 긴급 기준이면 경고.
- **이미 겹친 채 남은 데이터**(규칙 파일 직접 수정 등): 더 짧은 기준 적용(알림을 늦추는 쪽으로 틀리지 않게) + `care_state.rule_conflicts` → 화면 상단 배너. 발견 경위: 9/18 #7(10분)·#8(8시간)이 둘 다 켜져 #8이 몰래 이기고 102호 예외까지 사라졌었다.
- **고르는 화면**(사용자 지적: "물어보기만 하고 아무것도 할 수 없다"):
  - 새 규칙이 겹치면 생성 결과·승인 대기 카드 버튼이 **[기존 규칙 유지] / [새 규칙 적용 (기존 끄기)]**
  - 이미 겹친 규칙은 규칙 관리 맨 위 카드에서 **[#7 유지] / [#8 유지]** (`engine.keep_rule`, `/api/rules/<id>/keep`). 겹침 목록은 `/api/care`가 규칙 파일로 바로 계산(`rule_conflict_groups`) — 고른 즉시 사라진다
  - 예외("102호만 …")의 대상 규칙이 여럿이면 `needs_choice` + 후보 버튼 → 고르면 `/api/rules/<id>/override`로 그 규칙에 붙인다. **AI를 다시 부르지 않는다**
- 점검: `python test_rules.py`
- **엔진 네트워크 내성**: 플랫폼 요청에 10초 제한(`iot_platform.TIMEOUT_S`), 한 바퀴에서 `RequestException`이 나면 그 판정만 건너뛴다. 9/18 공용 서버 ReadTimeout 한 번에 엔진이 종료됐던 것. 장애 흉내 시험으로 생존 확인.

## 3. 결정과 이유 — 되돌리기 전에 이유가 아직 유효한지 확인할 것

| 결정 | 이유 | 확인 위치 |
|---|---|---|
| 세대 명단도 하드코딩 금지, `home=` 라벨로 발견 | 명제가 "하드코딩 제로" | `scope.discover_homes` |
| 세대 키는 `home=` | `unit=`은 측정단위(`unit=C`)로 이미 사용 | 라벨 전반 |
| 컨테이너 2분할: `h{호}_pir`(값 무관 주기 보고) + `h{호}_evt`(움직임 0→1 때만) | 둘을 합치면 무활동/두절 구분 불가. **게이트웨이가 `cra` 필터를 무시하고 `lim`도 최신순이 아니어서** 이력으로 마지막 움직임을 찾을 수 없음 → 이벤트 컨테이너 필수 | `home_node.ino` loop, `care_monitor.read_activity` |
| 판정 순서: 기기 → 생활 | 두절인데 무활동 타이머를 돌리면 전부 '긴급' 오탐 | `judge` ① 분기 |
| 판정 주체는 Watchdog sweep, 구독은 최적화 | 구독은 이벤트가 있을 때만 옴. 위험은 "아무 일 없음" | `engine.loop` |
| 두절 임계 `STALE_FACTOR(3) × report_s`, `report_s`는 **라벨**에서 | 전시 5초/운영 60초로 바뀌어도 서버 코드 불변 | `care_monitor._report_period` |
| sweep 주기 < 두절 임계 | 아니면 멀쩡한 세대 전부 '점검 필요' | `check_sweep_interval` |
| 무활동 기준 단위 = **분** (`idle_over_m`) | 시간 단위면 전시 축약값이 `0.0167`. LLM도 스스로 분을 만들어냄 | `scope.IDLE_OP` |
| 활동 CIN이 없으면 **컨테이너 `ct`** 를 기준점 | `None`이면 한 번도 안 움직인 세대가 조용히 '정상' | `read_activity`, `read_tree`가 `ct` 저장 |
| 값이 없으면 LLM이 채우지 않고 `value=""` → `needs_clarification` → 승인 대기, 값 없이 승인 거부 | AI가 임의 임계값을 넣는 것 자체가 신뢰성 결함 | `validate_scope`, `approve_rule` |
| 빈 값은 validator가 거부하지 않음 | 거부하면 되묻기 단계로 못 감 | `_check_type_condition` |
| 예외 대상 규칙은 **파이썬이 매칭**, LLM은 `{home,type,value}`만 | LLM이 규칙 ID를 고르면 환각이 판정에 섞임 | `_find_override_target` |
| 규칙 종류는 `scope`가 아니라 **`when`** 으로 판정 (`type`=돌봄, `path`=제어) | LLM이 제어 규칙에 `scope.homes="ALL"`을 넣어도 안 깨지게 | `validate_scope` 앞부분, `expand` |
| 새 규칙은 `pending` → 승인해야 실행, 승인자·시각 기록 | 전시 계획안 ③, 책임 기록 | `is_active` |
| `status` 없는 규칙은 approved 취급 | 승인 도입 전 규칙 호환 | `is_active` |
| **판단 근거(`basis`)는 고정 문자열**, AI 아님. `care_monitor`는 AI를 import하지 않음 | 판정과 근거가 어긋나면 안 됨. "LLM 껍데기" 방어선 | `judge` |
| "예외가 판정을 바꿈"은 **실제로 갈릴 때만** 표시, 두절 세대 제외 | 무조건 띄우면 화면이 거짓말 | `overrideChangedVerdict`, `scope.format_plan`은 판정 변화를 단정하지 않음 |
| 대표 시나리오는 **두 문장** (공통 규칙 → "102호만 …") | 한 문장이면 "시스템이 대상 규칙을 스스로 찾는" 증거 장면이 사라짐 | — |
| "대표 시나리오 실행" 버튼 없음 | 미리 짜둔 재생으로 보임 | — |
| 세대 관리는 구현, **통계 분석은 '준비 중' 메뉴로만** 둠 | 통계는 세대별 활동 이력 저장소가 있어야 의미가 있음. 알림 100건으로 낸 숫자는 테스트 기록이 섞여 운영 수치처럼 오해를 삼 | `App.vue` `NAV` |
| 기기 이상 색 = 보라, 생활 이상 = 초록/노랑/빨강 | 둘 다 주황이면 "사람 위험"과 "장치 두절"이 섞여 보임 | `dashboard/src/style.css` |
| 용어: 본문·UI **세대**, 제목·부제·통계청 인용은 **가구** | 제출본 고유명·인용은 소급 수정 안 함 | 제안서 |
| 알림 수신자 = 복지사 고정 | 규칙에 수신자 필드 불필요 | — |
| **"시연용 축약" 화면 표시 안 함**, 서버에 "운영 기준 8시간" 같은 값을 두지 않음 | 기준값은 복지사가 말한 대로 규칙에 들어가는 정책. 시스템이 "올바른 기준"을 전제하면 원칙과 어긋나고, 일부러 짧게 잡은 예외(102호 3분)까지 이상한 값처럼 보임. 시연에서는 **말로** 고지 | — |
| 판정 결과에 경과 초와 함께 **실제 시각**(`last_contact_at`·`last_activity_at`·`judged_at`)을 내보내고, 화면은 1초 시계(`format.js` `nowMs`)로 경과를 다시 계산 | 서버 숫자를 그대로 그리면 엔진이 멈춰도 "2초 전"이 굳어 거짓 표시. `판정 시각`이 30초 넘으면 "판정이 갱신되지 않음" | `care_monitor.judge`, `HomeBasis.vue` |
| `run_once`는 `when.path`가 없는 규칙(돌봄 규칙)을 건너뜀 | 돌봄 규칙은 Watchdog이 판정. 안 건너뛰면 4초마다 빈 경로로 공용 서버에 헛요청 + `(센서 못 읽음: )` 로그 | `engine.run_once` |

## 9. 작업 규칙

**플랫폼**
- 수업용 **공유** 서버다. 컨테이너 생성은 되돌리기 어렵다(삭제 403 사례 있음). 새 리소스를 만들기 전에 사용자에게 확인.
- 읽기는 자유. 쓰기 테스트는 기존 `h101~h105` 컨테이너 범위에서.

**테스트**
- `engine.add_rule_from_sentence` 등을 시험할 때는 **실제 `rules.json`을 건드리지 말 것.** `engine.RULES_FILE`, `engine.ALERTS_FILE`을 임시 경로로 바꿔서 실행.
- Gemini는 무료 티어(`gemini-3.1-flash-lite` → 429 시 `gemini-3.5-flash` 하루 20회). LLM 호출은 필요한 만큼만.
- 코드 수정 후: `python verify_report.py` 17/17 유지, 대시보드 수정 시 빌드 확인.
- `care_monitor.py`·`scope.py`·`engine.py` 판정 관련 수정 시 **엔진 재시작** 필요(모듈이 메모리에 로드됨).

**설계 원칙**
1. 기능 추가보다 입증.
2. 판정·검증·근거 문장에 AI를 넣지 않는다.
3. 조건부로만 참인 문구는 조건을 코드로 확인하고 띄운다.
4. 구현 안 한 것을 완료로 쓰지 않는다 (제안서 3분류: 완료 / 전시 예정 / 향후).
5. 제안서·대본에 인용된 수치는 실측값만. 동작이 바뀌면 문서도 같이 고친다.

**환경**
- Windows. 콘솔 한글 깨지면 `PYTHONUTF8=1`.
- 주석·문서는 한국어, 기존 파일처럼 "왜"를 주석으로 남기는 스타일.
- 실행: `python api_server.py`(:5001) · `npm run dev --prefix IOT/dashboard`(:5173) · `python -c "import engine; engine.loop(interval=4)"`
